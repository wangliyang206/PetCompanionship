# 宠物模型与动画规格（交付美术 / 产品）

> 目的：把「宠物要活起来」这件事，从口头需求变成可验收的交付清单。
> 适用：所有物种、所有成长阶段（卵 / 幼崽 / 成体 / 完全体）。
> 状态：2026-11-06 制定，**现行模型不满足**，需按本规格重做。

---

## 0. 结论：必须做骨骼，程序化动画到不了

实测当前 4 个阶段的 GLB（`mao_tuantuan_{egg,baby,adult,final}.glb`）：

| 项 | 实测值 | 说明 |
|---|---|---|
| 骨骼（skins） | **0** | 没有任何骨骼 |
| 动画（animations） | **0** | 没有任何动画剪辑 |
| 网格 | 1 个 primitive、17k~32k 顶点 | 单一静态网格 |
| 顶点属性 | POSITION / NORMAL / TEXCOORD_0 | **没有 JOINTS / WEIGHTS**（无蒙皮权重） |
| 几何结构 | 146 个碎片拼成的**空心壳** | 腿只是底部几个小凸起，不是独立肢体 |
| 贴图 | 3 张 4096²（albedo / normal / metallic-roughness） | 五官、花纹全部画在 albedo 上 |

**这意味着：代码能做的只有"整体位移 + 整体缩放/倾斜"。** 我们试过用程序化蒙皮（按空间区域给顶点算权重、在 CPU 上做形变）来伪造步态，实测结果是：能做出轻微晃动，**做不出抬腿、迈步、眨眼、张嘴**——因为这些部位在几何上根本不存在独立结构。

所以你要的那份清单（手脚动、卧下站起、扭头、嘴动、微表情、眨眼、蹦跑跳、快慢走、飞行），**只有带骨骼 + 形变键的模型能做到**。这条路是对的，而且是唯一的路。

---

## 1. 需求 → 技术手段对照

把需求拆到具体资产上，避免"做了骨骼但做不出眨眼"这种返工。

| 需求 | 靠什么实现 | 备注 |
|---|---|---|
| 手脚动、走路、跑步 | 四肢骨骼 + walk/run 动画 | 必须有独立肢体几何 |
| 卧下 / 站起 / 坐下 | 全身骨骼动画（sit_down / lie_down / stand_up） | 需要过渡动画，不能硬切 |
| 扭头 / 歪头 | 颈部 + 头部骨骼 | 建议 neck + head 两节，扭头才有弧线 |
| 嘴动（吃、叫） | **jaw 骨骼** 或 `mouth_open` 形变键 | 只有 jaw 骨骼张嘴会像"掉下巴"，建议配形变键 |
| 眨眼 | **眼睑形变键** `blink`（左/右可分开更好） | 眨眼必须随机触发，不能做进循环动画 |
| 微表情（眯眼、鼓腮、皱鼻） | 形变键 `eye_squint` / `cheek_puff` / `nose_twitch` | 与情绪状态绑定，不走动画剪辑 |
| 蹦 / 跳 | 骨骼动画 + 代码位移（关闭 root motion） | 起跳/滞空/落地拆 3 段 |
| 快慢走 | walk 动画 + 播放速率联动 | 用 timeScale 跟速度，避免脚滑 |
| 翅膀 / 飞行 | 翅膀骨骼（2~3 节）+ fly 系列动画 | 需要"贴地 → 起飞 → 悬停 → 降落"整套状态 |

## 2. 骨骼规范

### 2.1 统一骨架模板（所有物种共用）
用同一套命名，代码才能一套动画状态机跑所有宠物。**不同物种只增不减**，不要自创名字。

```
root                        # 原点（脚底中心），不做动画
└─ hips                     # 骨盆/重心，所有位移起伏的基准
   ├─ spine
   │  └─ chest
   │     ├─ neck
   │     │  └─ head
   │     │     ├─ ear_L / ear_R
   │     │     ├─ jaw                # 有嘴部动作才要
   │     │     └─ eyelid_L / eyelid_R  # 也可用形变键替代
   │     ├─ shoulder_L → upperArm_L → forearm_L → hand_L   # 前肢
   │     ├─ shoulder_R → upperArm_R → forearm_R → hand_R
   │     └─ wing_L_01 → wing_L_02 → wing_L_03               # 仅飞行物种
   │         wing_R_01 → wing_R_02 → wing_R_03
   ├─ thigh_L → shin_L → foot_L                             # 后肢
   ├─ thigh_R → shin_R → foot_R
   └─ tail_01 → tail_02 → tail_03 → tail_04                 # 2~4 节，按物种
```

### 2.2 硬性约束
- 单只骨骼数 **≤ 60**（不含末端辅助骨）；鱼/鸟可精简到 30 以内。
- 命名**全小写 + 下划线**，左右用 `_L` / `_R`（不要用 Left/Right 混写）。
- 层级里 `root → hips` 必须有；`root` 的位置固定不动（位移交给代码）。
- 每条腿至少 3 节（大腿/小腿/脚），否则走路会像"棍子摆"。
- 尾巴至少 3 节，摆尾才有 S 形。
- 翅膀至少 2 节，否则扇动像硬纸板。

## 3. 动画剪辑清单

### 3.1 通用必需（每个物种都要有）

| 剪辑名 | 循环 | 时长 | 触发 |
|---|---|---|---|
| `idle` | ✅ | 3~5s | 默认待机（呼吸 + 偶尔甩尾/竖耳） |
| `idle_alt` | ✅ | 3~5s | 待机变体，随机穿插，避免机械重复 |
| `walk` | ✅ | 1.0~1.4s/循环 | 慢速移动 |
| `run` | ✅ | 0.5~0.7s/循环 | 快速移动 |
| `jump_start` | ❌ | 0.2~0.3s | 起跳 |
| `jump_air` | ✅ | 0.4~0.6s | 滞空（可循环到落地） |
| `jump_land` | ❌ | 0.2~0.3s | 落地缓冲 |
| `sit_down` | ❌ | 0.5s | 坐下过渡 |
| `sit_idle` | ✅ | 4s | 坐姿待机 |
| `stand_up` | ❌ | 0.5s | 起身 |
| `lie_down` | ❌ | 0.6s | 趴下 |
| `lie_idle` | ✅ | 5s | 趴姿待机（睡觉用） |
| `sleep` | ✅ | 6s | 睡觉（呼吸幅度更大） |
| `turn_head_L/R` | ❌ | 0.4s | 扭头看 |
| `eat` | ✅ | 1.2s | 进食（嘴动 + 低头） |
| `happy` | ✅ | 1.0s | 开心（蹦跳 / 转圈） |
| `sad` | ✅ | 3s | 失落（低头垂尾） |
| `pet_react` | ❌ | 1.0s | 被抚摸（眯眼 + 蹭） |

### 3.2 飞行物种追加
`fly_takeoff`（0.4s）· `fly_idle`（悬停循环 1.0s）· `fly_forward`（循环 0.6s）· `fly_land`（0.4s）· `glide`（循环 2s，翅膀展开不扇）

### 3.3 制作要求
- **FPS 30**，导出时烘焙到 GLB 内嵌动画。
- **关闭 root motion**：所有剪辑原地播放，位移由代码控制（否则动画会把位置抢走）。
- 循环剪辑的首尾帧必须**完全对齐**（第 0 帧 = 最后一帧），否则会抽搐。
- 过渡剪辑（sit_down / stand_up / jump_*）要能在**任意时刻被打断**，最长不超过 0.6s。
- 不要把眨眼、甩尾这种"随机小动作"做进循环——它们要由代码随机触发，否则看久了很假。

## 4. 形变键（BlendShape / Morph Target）

眨眼、嘴动这类"局部小变形"，用骨骼不自然，用形变键最省事。

| 形变键 | 作用 | 必需 |
|---|---|---|
| `blink` | 双眼闭合 | ✅ 所有物种 |
| `blink_L` / `blink_R` | 单眼眨（可选，做 wink） | 可选 |
| `mouth_open` | 张嘴（叫、吃） | ✅ |
| `mouth_smile` | 嘴角上扬 | ✅ |
| `eye_squint` | 眯眼（被摸、开心） | ✅ |
| `cheek_puff` | 鼓腮（吃东西） | 可选 |
| `nose_twitch` | 鼻子抽动（嗅） | 可选 |
| `ear_perk` | 竖耳（警觉、期待） | 可选（有耳骨骼可用骨骼代替） |

约束：
- 单只形变键 **≤ 8 个**，单个形变**只动局部**（不要整脸一起推）。
- 形变键命名固定，代码要按名字调权重（0~1）。
- 眼睑如果是独立部件（不是形变），也可以，但要保证闭眼时**没有穿模**。

## 5. 导出与资产规范

| 项 | 要求 | 原因 |
|---|---|---|
| 朝向 | **正面朝 +Z**，Y 轴向上 | 引擎与漫游朝向约定一致（0° = +Z） |
| 原点 | **脚底中心**，y = 0 贴地 | 否则每只需要单独调偏移 |
| 单位 | 米，缩放 1.0，导出前 apply transform | 避免导入后尺寸不一 |
| 三角面 | 幼崽 ≤ 8k，成体 ≤ 15k，完全体 ≤ 25k | 现在 17k~32k 偏重，且低端机会掉帧 |
| 材质 | **单只 1 个材质**，不透明或简单透明 | 多材质 = 多次 drawcall |
| 贴图 | **1024² ×1 张**（图集：albedo + 可选 tint mask） | 现在 3 张 4096²，显存直接爆（低端机 GL_OUT_OF_MEMORY） |
| 着色 | 支持 unlit / 卡通 ramp | 美术贴图已带明暗，走 PBR 反而发灰 |
| 格式 | **GLB**，动画内嵌 | 少一层资源依赖 |
| 命名 | 文件 `{species_id}_{stage}.glb`，节点全英文小写 | 代码按名加载 |

**关于主题色**：如果 12 只宠物共用一套几何只换色，建议 albedo 画成"白底 + 一张 tint mask"，代码 `mainColor` 上色；否则每只都要单独出图，包体和维护成本都高。

## 6. 性能预算（目标机 Mali-T820 / 2GB 内存）

| 项 | 预算 | 备注 |
|---|---|---|
| 同时在场宠物 | 1 只主宠 + 最多 2 只背景 | 多于 1 只时用 LOD 简化 |
| 单只 drawcall | ≤ 2 | 1 材质 + 1 阴影 |
| 单只显存 | ≤ 8MB | 贴图 1024² + 网格 + 骨骼矩阵 |
| 动画 CPU | ≤ 1.5ms/帧 | 骨骼 ≤ 60 时没问题 |
| 包体 | 单只 ≤ 2MB | 现在单只 GLB 21~31MB，必须压 |

## 7. 验收清单（美术交付前自检）

- [ ] GLB 里有 `skins`（骨骼）和 `animations`（至少 idle/walk/run/sit_down/stand_up）
- [ ] 顶点属性含 `JOINTS_0` / `WEIGHTS_0`
- [ ] 正面朝 +Z，原点在脚底中心，Y=0 贴地
- [ ] `walk` 与 `run` 播放时**脚不打滑**（脚掌触地期间相对地面静止）
- [ ] 循环剪辑首尾帧对齐
- [ ] 眨眼/嘴动是形变键，不是做死在循环动画里
- [ ] 单材质、贴图 ≤ 1024²
- [ ] 三角面、骨骼数在预算内
- [ ] 在 Cocos 里用 `SkeletalAnimation` 能直接播（命名对得上）

## 8. 工程侧要配套做什么（模型到位后）

1. **动画状态机**：idle / walk / run / sit / lie / sleep / eat / fly 之间的切换与打断规则；
2. **步频与位移同步**：`anim.timeScale = 实际速度 / 剪辑设计速度`，从根上解决脚滑；
3. **表情层**：形变键权重独立于动画播放（眨眼随机 2~6s、情绪驱动眯眼）；
4. **飞行状态**：起飞 → 悬停 → 巡航 → 降落，配合高度曲线与落地缓冲；
5. **LOD**：远处切低模 + 降频动画。

## 9. 过渡方案（骨骼模型到位前）

模型重做有周期，这段时间不能一直"图片平移"。低成本过渡（不改模型、不改美术）：

- 移动从"匀速 tween"改为**速度驱动**：起步加速、到点减速、转身有过渡；
- 行走时加**身体起伏 + 左右重心转移 + 落地压扁**（程序化，不碰顶点）；
- 待机加**随机小动作**（歪头、抖毛、原地小跳），靠节点变换实现；
- 这一版只能做到"看起来在使劲走"，**做不到抬腿**——但比现在的匀速滑行好很多。
