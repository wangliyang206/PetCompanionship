# 宠物模型与动画规格（交付美术 / 产品）

> 目的：把「宠物要活起来」这件事，从口头需求变成可验收的交付清单。
> 适用：所有物种、所有成长阶段（卵 / 幼崽 / 成体 / 完全体）。
> 状态：2026-11-06 制定，**现行模型不满足**，需按本规格重做。

---

## 0. 结论：必须做骨骼，程序化动画到不了

实测当前 4 个阶段的 GLB（`mao_tuantuan_{egg,baby,adult,final}.glb`）：

| 项 | 实测值 | 说明 |
|---|---|---|
| 骨骼（skins） | **0** | 没有任何骨骼 |
| 动画（animations） | **0** | 没有任何动画剪辑 |
| 网格 | 1 个 primitive、17k~32k 顶点 | 单一静态网格 |
| 顶点属性 | POSITION / NORMAL / TEXCOORD_0 | **没有 JOINTS / WEIGHTS**（无蒙皮权重） |
| 几何结构 | 146 个碎片拼成的**空心壳** | 腿只是底部几个小凸起，不是独立肢体 |
| 贴图 | 3 张 4096²（albedo / normal / metallic-roughness） | 五官、花纹全部画在 albedo 上 |

**这意味着：代码能做的只有"整体位移 + 整体缩放/倾斜"。** 我们试过用程序化蒙皮（按空间区域给顶点算权重、在 CPU 上做形变）来伪造步态，实测结果是：能做出轻微晃动，**做不出抬腿、迈步、眨眼、张嘴**——因为这些部位在几何上根本不存在独立结构。

所以你要的那份清单（手脚动、卧下站起、扭头、嘴动、微表情、眨眼、蹦跑跳、快慢走、飞行），**只有带骨骼 + 形变键的模型能做到**。这条路是对的，而且是唯一的路。

---

## 1. 需求 → 技术手段对照

把需求拆到具体资产上，避免"做了骨骼但做不出眨眼"这种返工。

| 需求 | 靠什么实现 | 备注 |
|---|---|---|
| 手脚动、走路、跑步 | 四肢骨骼 + walk/run 动画 | 必须有独立肢体几何 |
| 卧下 / 站起 / 坐下 | 全身骨骼动画（sit_down / lie_down / stand_up） | 需要过渡动画，不能硬切 |
| 扭头 / 歪头 | 颈部 + 头部骨骼 | 建议 neck + head 两节，扭头才有弧线 |
| 嘴动（吃、叫） | **jaw 骨骼** 或 `mouth_open` 形变键 | 只有 jaw 骨骼张嘴会像"掉下巴"，建议配形变键 |
| 眨眼 | **眼睑形变键** `blink`（左/右可分开更好） | 眨眼必须随机触发，不能做进循环动画 |
| 微表情（眯眼、鼓腮、皱鼻） | 形变键 `eye_squint` / `cheek_puff` / `nose_twitch` | 与情绪状态绑定，不走动画剪辑 |
| 蹦 / 跳 | 骨骼动画 + 代码位移（关闭 root motion） | 起跳/滞空/落地拆 3 段 |
| 快慢走 | walk 动画 + 播放速率联动 | 用 timeScale 跟速度，避免脚滑 |
| 翅膀 / 飞行 | 翅膀骨骼（2~3 节）+ fly 系列动画 | 需要"贴地 → 起飞 → 悬停 → 降落"整套状态 |

## 2. 骨骼规范

### 2.1 统一骨架模板（所有物种共用）
用同一套命名，代码才能一套动画状态机跑所有宠物。**不同物种只增不减**，不要自创名字。

```
root                        # 原点（脚底中心），不做动画
└─ hips                     # 骨盆/重心，所有位移起伏的基准
   ├─ spine
   │  └─ chest
   │     ├─ neck
   │     │  └─ head
   │     │     ├─ ear_L / ear_R
   │     │     ├─ jaw                # 有嘴部动作才要
   │     │     └─ eyelid_L / eyelid_R  # 也可用形变键替代
   │     ├─ shoulder_L → upperArm_L → forearm_L → hand_L   # 前肢
   │     ├─ shoulder_R → upperArm_R → forearm_R → hand_R
   │     └─ wing_L_01 → wing_L_02 → wing_L_03               # 仅飞行物种
   │         wing_R_01 → wing_R_02 → wing_R_03
   ├─ thigh_L → shin_L → foot_L                             # 后肢
   ├─ thigh_R → shin_R → foot_R
   └─ tail_01 → tail_02 → tail_03 → tail_04                 # 2~4 节，按物种
```

### 2.2 硬性约束
- 单只骨骼数 **≤ 60**（不含末端辅助骨）；鱼/鸟可精简到 30 以内。
- 命名**全小写 + 下划线**，左右用 `_L` / `_R`（不要用 Left/Right 混写）。
- 层级里 `root → hips` 必须有；`root` 的位置固定不动（位移交给代码）。
- 每条腿至少 3 节（大腿/小腿/脚），否则走路会像"棍子摆"。
- 尾巴至少 3 节，摆尾才有 S 形。
- 翅膀至少 2 节，否则扇动像硬纸板。

## 3. 动画剪辑清单

### 3.1 通用必需（每个物种都要有）

| 剪辑名 | 循环 | 时长 | 触发 |
|---|---|---|---|
| `idle` | ✅ | 3~5s | 默认待机（呼吸 + 偶尔甩尾/竖耳） |
| `idle_alt` | ✅ | 3~5s | 待机变体，随机穿插，避免机械重复 |
| `walk` | ✅ | 1.0~1.4s/循环 | 慢速移动 |
| `run` | ✅ | 0.5~0.7s/循环 | 快速移动 |
| `jump_start` | ❌ | 0.2~0.3s | 起跳 |
| `jump_air` | ✅ | 0.4~0.6s | 滞空（可循环到落地） |
| `jump_land` | ❌ | 0.2~0.3s | 落地缓冲 |
| `sit_down` | ❌ | 0.5s | 坐下过渡 |
| `sit_idle` | ✅ | 4s | 坐姿待机 |
| `stand_up` | ❌ | 0.5s | 起身 |
| `lie_down` | ❌ | 0.6s | 趴下 |
| `lie_idle` | ✅ | 5s | 趴姿待机（睡觉用） |
| `sleep` | ✅ | 6s | 睡觉（呼吸幅度更大） |
| `turn_head_L/R` | ❌ | 0.4s | 扭头看 |
| `eat` | ✅ | 1.2s | 进食（嘴动 + 低头） |
| `happy` | ✅ | 1.0s | 开心（蹦跳 / 转圈） |
| `sad` | ✅ | 3s | 失落（低头垂尾） |
| `pet_react` | ❌ | 1.0s | 被抚摸（眯眼 + 蹭） |

### 3.2 飞行物种追加
`fly_takeoff`（0.4s）· `fly_idle`（悬停循环 1.0s）· `fly_forward`（循环 0.6s）· `fly_land`（0.4s）· `glide`（循环 2s，翅膀展开不扇）

### 3.3 制作要求
- **FPS 30**，导出时烘焙到 GLB 内嵌动画。
- **关闭 root motion**：所有剪辑原地播放，位移由代码控制（否则动画会把位置抢走）。
- 循环剪辑的首尾帧必须**完全对齐**（第 0 帧 = 最后一帧），否则会抽搐。
- 过渡剪辑（sit_down / stand_up / jump_*）要能在**任意时刻被打断**，最长不超过 0.6s。
- 不要把眨眼、甩尾这种"随机小动作"做进循环——它们要由代码随机触发，否则看久了很假。

## 4. 形变键（BlendShape / Morph Target）

眨眼、嘴动这类"局部小变形"，用骨骼不自然，用形变键最省事。

| 形变键 | 作用 | 必需 |
|---|---|---|
| `blink` | 双眼闭合 | ✅ 所有物种 |
| `blink_L` / `blink_R` | 单眼眨（可选，做 wink） | 可选 |
| `mouth_open` | 张嘴（叫、吃） | ✅ |
| `mouth_smile` | 嘴角上扬 | ✅ |
| `eye_squint` | 眯眼（被摸、开心） | ✅ |
| `cheek_puff` | 鼓腮（吃东西） | 可选 |
| `nose_twitch` | 鼻子抽动（嗅） | 可选 |
| `ear_perk` | 竖耳（警觉、期待） | 可选（有耳骨骼可用骨骼代替） |

约束：
- 单只形变键 **≤ 8 个**，单个形变**只动局部**（不要整脸一起推）。
- 形变键命名固定，代码要按名字调权重（0~1）。
- 眼睑如果是独立部件（不是形变），也可以，但要保证闭眼时**没有穿模**。

## 5. 导出与资产规范

| 项 | 要求 | 原因 |
|---|---|---|
| 朝向 | **正面朝 +Z**，Y 轴向上 | 引擎与漫游朝向约定一致（0° = +Z） |
| 原点 | **脚底中心**，y = 0 贴地 | 否则每只需要单独调偏移 |
| 单位 | 米，缩放 1.0，导出前 apply transform | 避免导入后尺寸不一 |
| 三角面 | 幼崽 ≤ 8k，成体 ≤ 15k，完全体 ≤ 25k | 现在 17k~32k 偏重，且低端机会掉帧 |
| 材质 | **单只 1 个材质**，不透明或简单透明 | 多材质 = 多次 drawcall |
| 贴图 | **1024² ×1 张**（图集：albedo + 可选 tint mask） | 现在 3 张 4096²，显存直接爆（低端机 GL_OUT_OF_MEMORY） |
| 着色 | 支持 unlit / 卡通 ramp | 美术贴图已带明暗，走 PBR 反而发灰 |
| 格式 | **GLB**，动画内嵌 | 少一层资源依赖 |
| 命名 | 文件 `{species_id}_{stage}.glb`，节点全英文小写 | 代码按名加载 |

**关于主题色**：如果 12 只宠物共用一套几何只换色，建议 albedo 画成"白底 + 一张 tint mask"，代码 `mainColor` 上色；否则每只都要单独出图，包体和维护成本都高。

## 8. 工程侧要配套做什么（模型到位后）

1. **动画状态机**：idle / walk / run / sit / lie / sleep / eat / fly 之间的切换与打断规则；
2. **步频与位移同步**：`anim.timeScale = 实际速度 / 剪辑设计速度`，从根上解决脚滑；
3. **表情层**：形变键权重独立于动画播放（眨眼随机 2~6s、情绪驱动眯眼）；
4. **飞行状态**：起飞 → 悬停 → 巡航 → 降落，配合高度曲线与落地缓冲；
5. **LOD**：远处切低模 + 降频动画。

## 9. 过渡方案（骨骼模型到位前）

模型重做有周期，这段时间不能一直"图片平移"。低成本过渡（不改模型、不改美术）：

- 移动从"匀速 tween"改为**速度驱动**：起步加速、到点减速、转身有过渡；
- 行走时加**身体起伏 + 左右重心转移 + 落地压扁**（程序化，不碰顶点）；
- 待机加**随机小动作**（歪头、抖毛、原地小跳），靠节点变换实现；
- 这一版只能做到"看起来在使劲走"，**做不到抬腿**——但比现在的匀速滑行好很多。

## 10. 生成管线与积分方案（2026-11-06 补充，回答"改现有模型 vs 重新生成"）

### 10.1 结论：**重新生成更省积分，给现有模型绑骨是双倍浪费**

现有模型是"146 块碎片拼成的空心壳"：腿只是身体底部的凸起，五官是贴图上画的像素。
Tripo 的自动绑骨（绑骨检查免费 / 自动绑骨 25 积分，支持四足 v2.5 算法）**技术上能跑**，但：

| 问题 | 后果 |
|---|---|
| 腿不是独立肢体，自动绑骨分不出肩/肘/髋/膝 | 绑完抬腿幅度 ≈ 0，走路还是"整体蹭" |
| 五官是贴图像素，没有几何 | 眨眼、张嘴、微表情**连形变键都做不了**（无几何可变形） |
| 空心壳 + 146 连通块 | 蒙皮权重会跨部位串，一动就撕裂 |
| 21~31MB / 3×4096² 贴图 | 绑骨前必须先重拓扑（10~40 积分）+ 重贴图（10~30 积分），又是一笔钱 |

**账（单个模型、单个成长阶段）**

| 路线 | 积分 | 结果 |
|---|---|---|
| A：给现有模型绑骨 | 25(绑骨) + 10~40(重拓扑) + 10~30(重贴图) + 5~10(转换) ≈ **50~105** | 能动但动不好，最后仍要重做 → 积分×2 |
| B：换生成方式重做 | 5(概念图) + 20~30(图生3D) + 25(绑骨) ≈ **50~60** | 一次到位，天生适合绑骨 |

### 10.2 重新生成的正确姿势（积分省在哪）

关键不是"多花一次生成钱"，而是**换生成方式**，让模型天生适合绑骨：

1. **图生3D 代替文生3D**（20~30 积分）：文生3D 控制不了姿态（现在团团的蜷坐姿就是这么来的）。
   先用文生图（5 积分）出"标准四足站姿、四肢分开清晰可见、无遮挡、卡通低模"的概念图（正/侧/背三视图更稳），再图生3D。
2. **生成时直接限面数**（幼崽 ≤8k / 成体 ≤15k / 完全体 ≤25k），省掉重拓扑环节。
3. **单材质 + 1024² 贴图**选项一步到位。
4. **蛋不需要绑骨**：蛋壳破壳用 2D 美术/粒子表现（见 2.2.3 孵化视觉需求），不要为蛋花绑骨钱。

### 10.3 动画成本：一套共享动画库，绝不按"每只每段"生成

- **前提（对 §2 的硬性升级）**：所有宠物的骨骼**层级、命名、数量必须逐字一致**（不只是"用同一模板"）——骨骼位置/长度可以按物种不同，但结构必须一字不差。这样**一份动画剪辑可以直接播给所有宠物**，动画库零重复成本。
- **禁止**：每只宠物每段动画单独生成（29 只 × 18 段 × 20 积分 ≈ 10,440 积分 ≈ ¥730，且风格无法统一）。
- 动画库获取方式（三选一）：
  | 方案 | 成本 | 说明 |
  |---|---|---|
  | ① Blender 自制一套 18 段 | 0 积分，人工投入 | 对照 §2 模板骨架做，最可控，**推荐** |
  | ② Tripo 文本生成动作 | 20 积分/段 × 18 ≈ 360 积分（¥25，一次性） | 四足质量未验证，先用 1 只试点 |
  | ③ 买现成四足动画包 | $20~40（约 ¥150~300） | 重定向到模板骨架，注意版权可商用 |

### 10.4 AI 管线的两个现实修正（对 §4 的修订）

1. **AI 生成管线不产形变键**。眨眼/嘴动的落地方式改为：
   - 眼睑、下颌做成**独立小网格 + 骨骼**（`eyelid_L/R`、`jaw`），让自动绑骨能命中——这是 AI 管线里唯一走得通的路；
   - 形变键（`mouth_smile`/`eye_squint` 等）降级为**人工增强项**：只给完全体和主角宠物在 Blender 里补。
2. **自动绑骨的骨骼命名不会按我们的模板来**（Tripo 非人形走 v2.5 自有命名）。绑骨完成后需要一步**脚本重命名/映射到 §2 模板命名**，这一步做进资产管线，验收清单 §7 增加："骨架可一键映射到模板命名"。

### 10.5 试点先行（控制风险的最小花费）

先花最小积分跑通全链路，**验收通过再批量**：

```
团团幼崽单只试点：

  合计 ≈ 115 积分 ≈ ¥8
验收点：抬腿可见、眨眼(眼睑骨骼)可见、Cocos SkeletalAnimation 直接播、面数/贴图达标
```

全量估算（29 只：五虫 25 + 四猴 4，蛋不绑骨）：
29×5(概念图) + 29×4×25(生成) + 29×3×25(绑骨) + 动画库一次性 ≈ **5,220 积分 ≈ ¥365**。
若采用"同系共用基础网格、靠贴图配色区分"可压到 **~900 积分 ≈ ¥63**，代价是同系内形象差异变小——是否接受，待用户拍板。

### 10.6 零成本管线：Blender + Rigify

#### 10.6.1 先说清哪些"AI 免费绑骨"走不通

| 方案 | 免费？ | 结论 |
|---|---|---|
| **UniRig**（Tripo 自动绑骨背后的开源算法，支持四足/翅膀/尾巴） | 开源免费 | ❌ 需 NVIDIA GPU ≥8GB；本机是 AMD 核显 + 16GB 内存，跑不动（CPU 模式慢到不可用），租云 GPU 又要花钱 |
| **Mixamo** | 免费 | ❌ 只支持人形，四足用不上 |
| **Mesh2Motion / 各类网页绑骨** | 免费 | △ 面向人形，四足支持有限，不作为主路线 |
| **Tripo Studio 注册赠 300 金币** | 已赠，不额外花钱 | ✅ 绑骨 20 金币/只 → 够绑 9~15 个，**先拿来跑对照试验** |

#### 10.6.2 主路线：Blender（免费）+ Rigify（免费，Blender 内置）

Rigify 是 Blender 自带插件，**元骨架包含 Basic Quadruped / Cat / Wolf / Horse / Shark**——正好覆盖我们的体型，不用买 Auto-Rig Pro。

四套母骨架（对应体型家族，同家族共用一套，只需精调一次）：

| 家族 | 元骨架 | 覆盖 |
|---|---|---|
| A 四足小型 | `Cat` | 团团（橘猫）、阿绒（仓鼠型）、狐/狗/鼠类 |
| B 四足中大型 | `Wolf` / `Horse` | 牛/马/鹿类 |
| C 有翼 | `Basic Quadruped` + 手加 `wing_L_01~03` / `wing_R_01~03` | 鸟、有翅虫 |
| D 无肢 / 水生 | `Shark` | 鱼、蛇、软体虫 |

#### 10.6.3 批量脚本流程（bpy，写一次之后一键跑）

```
导入 GLB
 → 清理：merge by distance → 重算法线 → 删内部面 → apply transform
 → 包围盒对齐母骨架（Z 高、Y 长、四腿 XY 按比例缩放）
 → parent_set(type='ARMATURE_AUTO')   # Blender 自动权重
 → DEF- 骨重命名为 §2 模板命名（映射表脚本化）
 → 只导 DEF 骨，导出 GLB
```

两个硬前提（省不掉，省了就废）：
1. **清理必须做**：自动权重用的是骨热扩散算法，要求封闭流形网格。AI 生成的"146 碎片空心壳"不清理必然失败（表现为权重乱串、一动就撕裂）。
2. **生成姿态必须标准**（回到 §10.2）：四肢分开站立、腿不被身体遮挡。姿态不标准时骨架对不齐，自动权重就贴不到腿上——这是免费路线最依赖的一环，因为没钱买"智能绑骨"兜底。

> **2026-11-09 实装更新（D43）**：以上流程已由 `tools/rig/rig_pet2.py` 完全实现并跑通 2 只（长风幼崽/团团幼崽），实际管线比本节初稿更强：
> - **骨架不用母骨架对齐，而是按顶点分布几何拟合**，且自动识别两种头型：
>   - **直立型**（垂耳兔坐姿，长风）：颈部=宽度剖面局部极小，头骨从颈部向上；
>   - **前置型**（仓鼠/龙猫蹲伏团子，团团）：头是前上方大球（≥15% 顶点且明显偏前），hips/chest 贯穿身体球、head 骨竖直插进头球内部。**骨头必须走进各自的体块**，否则热扩散会把头部顶点分给躯干骨，一动脸就变形；
> - 检测不到耳/脚就不建对应骨骼（自动降级），**权重后处理（距离半径清洗/分区钳制）实测有害，禁止使用**——热扩散的大面积微小混合视觉上是柔和过渡；
> - 每段动画全骨骼静止姿势打底防导出污染；导出白名单只带目标 mesh；贴图压到 1024²、减面到 8000 tris（GLB ≈2.7MB）；
> - **验收标准**：① 渲染 8 帧（静止/扭头/走路×2/腾空/落地）逐帧目检无可见变形；② 形状畸变 p99 ≤ ~21%（与已验收的长风 18.3% 同档，>2% 的内置告警阈值对真实 AI 网格过严，仅作趋势参考）；③ 解 GLB 二进制复核 meshes=1、skins=1、3 段动画齐全。
