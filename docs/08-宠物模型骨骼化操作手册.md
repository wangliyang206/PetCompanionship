## 2. 输入：源模型要求

- 输入 = AI 生成（如 Tripo）的**静态**宠物模型 GLB，位于 `models/<宠物名>/`，每只宠物有 baby（幼年）/final（完全体）等成长阶段。
- **蛋（egg）不绑骨**——蛋是道具，不动画。
- 源模型常见状态（不用修，管线会处理）：
  - GLB 按 UV 拆点导致"上百个碎片岛"的假象，实际 `remove_doubles` 后是单一连通体；
  - 面数 30000、贴图 4096²，管线自动减面到 8000、贴图压到 1024²（GLB ≈2.7MB）；
  - 姿态最好是标准蹲坐/站立，四肢可见。姿态太歪时骨架拟合质量会下降。

## 3. 一键执行（主流程）

在项目根目录 `E:/git/PetCompanionship` 下：

```bash
BLENDER="E:/tools/blender45/blender-4.5.3-windows-x64/blender.exe"

"$BLENDER" -b -P tools/rig/rig_pet2.py -- \
  --input  "E:/git/PetCompanionship/models/tuantuan_baby/tuantuan_baby.glb" \
  --plan   chibi \
  --out    "E:/git/PetCompanionship/models/rigged/tuantuan_baby_rigged.glb" \
  --renders "E:/git/PetCompanionship/models/rigged/previews4"
```

### 3.1 参数说明

| 参数 | 默认 | 说明 |
|---|---|---|
| `--input` | 必填 | 源 GLB（绝对路径） |
| `--out` | 必填 | 输出 rigged GLB（绝对路径），命名约定 `<宠物名>_rigged.glb` 放 `models/rigged/` |
| `--renders` | 空 | 渲染验证图输出目录（绝对路径），约定 `models/rigged/previews<N>/`，N 递增 |
| `--plan` | chibi | chibi=Q版幼崽；quadruped=标准四足。当前动画两种通用，幼崽一律 chibi |
| `--facing` | -Y | 模型正面朝向。AI 生成模型默认 -Y，若渲出来背面朝镜头改 +Y |
| `--height` | 0.35 | 归一化后的模型高度（Blender 单位），勿改 |
| `--max-tris` | 8000 | 减面上限，勿改 |
| `--tex-size` | 1024 | 贴图尺寸上限，勿改 |
| `--no-legs` | 关 | 强制不建腿骨（走路用整体弹跳）。检测不到脚时会自动降级，一般不用手动加 |
| `--mode` | smooth | smooth=减面焊接后自动权重（**默认且已验证**）；rigid=岛级刚性零变形，仅对多岛碎片模型有意义，单连通体上会退化成"整只一块"（禁用） |

### 3.2 管线内部做了什么（理解顺序很重要）

1. **导入 + 合并 + 清理**：合并所有 mesh、`remove_doubles` 焊接 UV 拆点、删游离元素、法线一致、apply transform。
2. **归一化**：缩放到 `--height` 高度、底面落地、居中。
3. **岛分析**（必须在减面**之前**，Decimate 会焊掉岛信息）。
4. **几何拟合分析**（`analyze_geom`）：
   - 脚 = 底部 z<0.2H、前方、左右分开的小簇；
   - **头型二选一**（详见第 4 节）；
   - 耳 = 依头型分区的每侧最外侧细长顶点带；检测不到就自动不建该骨骼。
5. **建骨架**：8 骨模板 root/hips/chest/head/ear_L/ear_R/thigh_L/thigh_R，骨骼位置全部按拟合结果放置。
6. **自动权重**（骨热扩散）。
7. **动画**：3 段（idle 96 帧呼吸+摆头+耳抖 / walk 36 帧弹跳步态 / happy 36 帧腾空+挤压拉伸+耳甩），全部用均匀缩放和微小摆幅，**每段动画先为全骨骼打静止姿势底层关键帧**（防导出器把上一动作残留烘焙进来）。
8. **自检**：逐帧算三角形相似度 p99（见第 6 节解读）。
9. **导出 GLB**：白名单只导目标 mesh + 骨架（防场景杂项混入）， ACTIONS 模式分段导出动画。
10. **渲染 8 帧验证图**（Cycles CPU，约几秒）。

## 4. 头型识别与骨架匹配（本管线核心经验，必读）

宠物有两种体型家族，骨架布局完全不同。**骨头必须走进各自的体块，否则热扩散会把顶点分错家，一动就变形。**

| | 直立型 | 前置型 |
|---|---|---|
| 典型 | 垂耳兔坐姿（长风） | 仓鼠/龙猫蹲伏团子（团团） |
| 特征 | 头在躯干**上方**，颈部有明显宽度收窄 | 头是前上方**大球**（可占 40%+ 顶点），没有细脖子 |
| 骨架 | hips/chest 竖柱自下而上，head 从颈部向上 | hips/chest **贯穿身体球**，head 骨**竖直插进头球内部** |
| 耳朵检测区 | 上半身（0.28H~0.96H）最外侧带，z 跨度>0.24H | **头球中心以上**的最外侧带（避开腮部绒毛误判），z 跨度>0.10H |

脚本已自动识别（检测逻辑：前上方 0.42L×0.30H 区域顶点 ≥15% 且质心明显偏前 → 前置型），运行日志会打印：

```
[analyze] 头型=前置(团子) z_head=... 
[analyze] 头球质心=(+0.001,-0.165,+0.232) 身体质心=(+0.003,+0.048,+0.126)
[analyze] 耳L[...] 耳R[...]
[analyze] 脚L[...] 脚R[...]
```

**务必检查这四行日志**：头球质心是否真的落在头部（看渲染图对照）、耳朵 z 区间是否在头顶、脚的左右 x 是否对称。发现明显错位（比如耳朵检到了腮帮子）时，参考 D43 调整 `analyze_geom` 的分区阈值。

## 5. 验证流程（三关，全部通过才算完成）

### 5.1 渲染目检（第一关，最重要）

`--renders` 目录会出 8 张图：`pure_rest / rest_front / idle_mid / idle_headturn / walk_up / walk_down / happy_air / happy_land`。

逐张检查：整体轮廓正常、贴图正常、头/耳/身/前后脚无拉伸撕裂错位、扭头时脸部五官跟随头部而不是被身体拽走、腾空帧四肢自然。

- 看不清就跑特写：`"$BLENDER" -b -P tools/rig/closeup.py -- --input <成品glb> --action happy --frame 15 --out <目录>`
- 用户此前的两次投诉都是渲染/游戏里可见的变形，**目检不过不许交付**。

### 5.2 数值复算（第二关）

```bash
"$BLENDER" -b -P tools/rig/verify_glb.py -- --input "E:/git/PetCompanionship/models/rigged/xxx_rigged.glb"
```

输出 `p99`（三角形相似度畸变的 99 分位）。**验收基线：p99 ≤ ~21%**（长风兔 18.3%、团团 20.8% 均为目检通过的实绩）。脚本内置的 ">2% 告警"对真实 AI 网格过严（胡须等细长三角形随头转动的自然弯曲也会触发），只作趋势参考，不作为否决项。p99 突然翻倍（>30%）说明有问题，用 `locate_deform.py` 定位。

### 5.3 GLB 二进制复核（第三关）

```bash
python -c "
import struct, json
f='models/rigged/xxx_rigged.glb'
fh=open(f,'rb'); fh.read(12); clen,_=struct.unpack('<I4s',fh.read(8)); js=json.loads(fh.read(clen))
print('meshes=',[m.get('name') for m in js.get('meshes',[])],'skins=',len(js.get('skins',[])),'anims=',[a.get('name') for a in js.get('animations',[])])"
```

要求：`meshes=['node_0']`（或唯一的模型 mesh）、`skins=1`、`anims=['happy','idle','walk']`。出现第二个 mesh = 场景杂项混入（历史事故：42 顶点 Icosphere），必须排查。

## 6. 疑难对照表（实测踩过的坑，按症状查）

| 症状 | 原因 | 解法 |
|---|---|---|
| 扭头时脸跟着身体歪、五官变形 | 骨架与体型不匹配：头骨悬空在体块外，头部顶点被热扩散分给躯干 | 见第 4 节头型分支；用 `locate_deform.py` 确认偏差位置在脸区 |
| 单独转耳朵，下巴/嘴变形 | 耳权重渗到脸部 | **不要做权重手术**（实测两种方案都更糟，见下）；确认耳骨位置在头顶后重跑 |
| 走路时肚子跟着腿扭 | 腿骨权重污染躯干 | 确认腿骨真的插在腿/脚体块内；团子体型可 `--no-legs` 改整体弹跳步态 |
| walk 动画里混入 idle 的扭头、happy 的耳朵 | glTF 导出器全量烘焙骨骼姿势，未 keyframe 的骨带入上一动作残留 | 管线已内置修复（每段动画全骨骼静止姿势打底）；自建动画时必须照做 |
| 渲染图/成品里出现一个看不出来但二进制里存在的 Icosphere | Blender 4.5 glTF **导入器**会生成辅助形状（在 `glTF_not_exported` 集合），不是文件内容 | GLB 二进制里 meshes=1 就是干净的；分析脚本选 mesh 必须取**顶点最多者** |
| 渲染图落到了 C 盘根目录 | `--renders` 传了相对路径 | 一律绝对路径 |
| 自动权重失败（RuntimeError） | 网格非封闭流形 | 检查 `remove_doubles` 是否执行；仍失败则该模型可能是真碎片结构，考虑 rigid 模式或先修模 |
| rigid 模式下整只僵硬不动 | 单连通体只有 1 个岛，全部顶点绑到同一骨 | 正常现象；单连通体必须用 smooth 模式 |
| p99 高但渲染看不出问题 | 细长三角形（胡须/耳尖）随头部自然弯曲 | 属正常，以渲染目检为准 |

**权重后处理禁令（D43 两次实测证伪，勿再试）**：
1. 按骨骼距离设影响半径清洗权重 → 团子体型上"离腿骨近"的是肚皮不是腿，p99 32%→89%；
2. 分区钳制耳权重 → 热扩散的权重是平滑渐变，硬钳制造接缝撕裂，p99 20.7%→27.4%。
正确解法永远是把骨架位置修对（第 4 节），不是动权重。

## 9. 动画参数速查（要调风格时改这里）

都在 `rig_pet2.py` 的 `make_actions()`，改完重跑管线即可：

| 动画 | 关键参数 | 当前值 | 调整边界 |
|---|---|---|---|
| idle | hips 呼吸缩放 | 1.000→1.022 | ≤1.03，超过会有"胖瘦呼吸"感 |
| idle | head 摆头 yaw / pitch | ±7° / 3° | yaw ≤10° |
| idle | 耳抖 | ±6° | 按耳长缩放 |
| walk | root 弹跳 | ±0.012 | ≤0.02 |
| walk | hips 俯仰/侧倾 | ±2° | ≤4°，超了明显晃 |
| walk | 腿摆（有腿骨时） | ±0.16rad(9°) | chibi 短腿 ≤0.16，标准四足 ≤0.30 |
| happy | 腾空高度 | 0.075 | ≤0.10 |
| happy | 挤压拉伸 | 0.94→1.06（均匀缩放） | 只能用**均匀**缩放，各向异性会畸变 |
| happy | 耳后甩 | -22° | 按耳长缩放 |

铁律：**动画只用旋转 + 均匀缩放 + 平移**，任何各向异性缩放/剪切都会让三角形相似度爆表。
